# Marco R2 · Identidade real — resumo parcial

**Data:** 08/10/2026 · **Ramo:** `feature/geandre-r2-auth-ci` (PR #102, empilhado no #101).
**Contexto:** o R2 depende de um projeto Supabase na nuvem para a demonstração ao vivo, e a máquina da dupla não roda Docker. Mesmo assim, o job `db` do CI sobe um Supabase completo (**Auth/GoTrue + PostgREST + Postgres**). A parte do R2 que se prova com testes foi feita ali.

## O que mudou
- **`packages/politicas/src/http.test.ts`**: 7 testes pela API pública, com usuários fictícios criados pela API admin e **login com senha** (JWT real do GoTrue). Todos verdes no CI:
  1. Anônimo não lê nada.
  2. ⭐ **Exemplo 3**: docente com token **válido** lendo `notas_clinicas` → **42501 (403)**, por tabela e por RPC.
  3. Docente não forja consentimento e não lê a coluna do laudo; lê só o permitido.
  4. Pessoa autenticada sem vínculo vê 0 estudantes.
  5. **TOTP real (D-32)**: profissional negado em `aal1`. Depois de cadastrar e verificar um fator (código RFC 6238 gerado no teste), a sessão vira `aal2`, ele lê a nota, e a família vê a leitura na trilha.
  6. Coordenação: negada em `aal1`, cadastra em `aal2`.
  7. **RN08 pela API**: responsável revoga e o docente perde a escrita na hora.
- **Defeito real encontrado e corrigido.** `[auth.email] enable_signup = false` (que eu tinha posto no R1) **desliga o login por e-mail inteiro**. O bloqueio de autocadastro é o `[auth] enable_signup = false`. Sem esse teste, o erro só apareceria no dia da demonstração.
- O CI agora **falha** se URL ou chaves do Supabase faltarem: nada de "pulado em silêncio".

## O que falta no R2
- R2.1: Edge Function `convidar` + `scripts/implantar-escola.ts` (convite por e-mail, uso único, validade).
- R2.2: telas de entrar com senha, aceitar convite, recuperar senha, cadastrar e desafiar TOTP.
- R2.3/R3.5: `supabaseApi` implementando `PeiVivoApi` (sempre listando colunas; nunca `select *`).
- R2.4: guarda de rota aal2 e inatividade de 30 min.
- Projeto Supabase na nuvem para a demonstração **(decisão e conta da dupla)**.

## O que me preocupa
- O teste cria e apaga dados no Supabase **efêmero** do CI. Ele **nunca** deve apontar para um projeto com dados reais: as variáveis vêm só do `supabase status` do runner.
